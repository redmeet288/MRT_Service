# МРТ ТОЧНО — CRM направляющих врачей

Внутреннее веб-приложение для медпредставителей МРТ-направления: учёт направляющих врачей (НВ), лечебно-профилактических учреждений (ЛПУ), заявок на обследования, визитов, отчётности и справочников.

**Версия:** 1.5 (базовая поставка + пакеты доработок 1.1–1.4 и mobile-first редизайн)
**Дата выпуска:** октябрь 2026

---

## 1. Возможности системы

| Раздел | Что умеет |
|---|---|
| **Рабочий стол** | KPI-показатели (НВ, ЛПУ, Заявки, Визиты) с переходами в разделы; область данных «Все НВ / Только мои»; «Динамика заявок» с расшифровкой по периоду; «Рейтинг врачей» (топ-10); «Ближайшие визиты» |
| **Направляющие врачи** | Список в стиле 1С с сортировкой, карточка НВ, специализации (мультивыбор), график работы, привязка к ЛПУ, импорт/экспорт XLSX |
| **Заявки** | Список с сортировкой и фильтрами, карточка заявки, комментарий, «Что назначено» / «Что сделано» — множественный выбор из номенклатуры, «Куда направление» (по умолчанию «МРТ ТОЧНО»). При создании обязательны только «Дата» (предзаполнена) и «ФИО пациента»: если пациент не помнит врача, НВ/ЛПУ оставляются незаполненными, а обрывочная информация фиксируется в «Комментарии» |
| **Визиты и календарь** | Календарь «Месяц / Неделя / День» (почасовая сетка), клик по дню → расписание дня, перетаскивание визитов мышью на десктопе (между днями и по времени, точность 15 мин) с сохранением в БД, дата и время в карточке визита, мини-календарь месяца в боковой панели; на смартфоне перенос выполняется через карточку визита (нативные поля даты/времени) |
| **Мобильный режим (mobile-first)** | Работа со смартфона на приёме у врача: нижняя навигация с крупными тач-зонами и меню «Ещё», тёмный топ-бар с названием раздела, карточки заявок вместо таблиц, формы заявки и визита в виде нижних листов (bottom-sheet) с закреплёнными кнопками и крупными полями, кнопки быстрых действий (FAB) «Зарегистрировать заявку» и «Запланировать визит», мобильный календарь: «Месяц» — компактные ячейки с точками-индикаторами статусов, «Неделя» — вертикальный список дней, «День» — почасовые слоты с быстрым планированием; учёт safe-area (вырезы/жест-бар iPhone) |
| **Отчёты** | Отчёт «По обследованиям» в стиле 1С: настройки (период, МП, ЛПУ, НВ, номенклатура), 4 варианта группировки, сортировка столбцов, пресеты; экспорт **Excel** с иерархией (уровни сворачиваются/разворачиваются) и **PDF** кириллицей |
| **Справочники** | Отдельная страница со списком справочников: Направляющие врачи, ЛПУ, Города, Номенклатура, Специализация, Статусы сотрудничества; настройка видимости и порядка столбцов; импорт/экспорт XLSX внутри каждого справочника |
| **Пользователи** | Список с сортировкой по столбцам, создание/редактирование, роли |
| **Пометка «на удаление»** | Мягкое удаление в духе 1С: НВ, ЛПУ, номенклатура, специализации и пользователи не удаляются физически, а помечаются бейджем «Помечен(о) на удаление» (запись зачёркнута); помеченные исключаются из всех выпадающих списков и фильтров (заявки, визиты, отчёты, привязки), но остаются видимыми в списках; восстановление — одной кнопкой «Вернуть в работу» |
| **Журнал аудита** | Записи о входах, изменениях данных и выгрузках |

**Роли:**
- **МП (медпредставитель)** — полный доступ ко всем разделам;
- **Оператор** — рабочее место с ограничениями: только «Врачи (НВ)» и «Заявки»; при добавлении НВ обязательным является только ФИО (закрепление за МП выполняется позднее); закрытые API недоступны (403).

Прочее: интерфейс списочных форм в стиле 1С (в корпоративной палитре брендбука), оригинальный логотип «МРТ ТОЧНО» (белая версия на тёмном фоне — панель входа и боковая панель; цветная на светлом — мобильный вход и подвал; фирменный favicon), кнопка «Назад» браузера работает внутри приложения, mobile-first режим на смартфонах при сохранении десктопного 1С-интерфейса, тост-уведомления.

## 2. Технологии

- Next.js 16 (App Router), TypeScript 5, React 19
- Tailwind CSS 4 + shadcn/ui (компоненты интерфейса), Lucide Icons
- Prisma ORM + SQLite (файл `db/custom.db`)
- NextAuth v4 (вход по логину/паролю, JWT-сессии, роли)
- TanStack Query (данные), Zustand (состояние интерфейса)
- Recharts (диаграммы), @dnd-kit (перетаскивание визитов)
- SheetJS (xlsx) — импорт/экспорт; jsPDF + шрифт PT Sans — PDF с кириллицей

## 3. Требования к серверу / рабочей машине

- Node.js **20+** и один из пакетных менеджеров. Проверено на **Bun 1.2+** (рекомендуется), совместимо с npm.
- ОС: Windows / Linux / macOS.
- Браузер: актуальные Chrome, Edge, Firefox, Safari (разработка и приёмка выполнены в Chrome); поддерживаются мобильные браузеры Android/iOS — интерфейс адаптирован под смартфоны (mobile-first).

## 4. Быстрый запуск (режим разработки)

```bash
# 1. Распакуйте архив исходников в отдельную папку и перейдите в неё
# 2. Установите зависимости
bun install          # или: npm install

# 3. Проверьте файл .env — укажите АБСОЛЮТНЫЙ путь к файлу базы данных:
#    DATABASE_URL=file:/полный/путь/к/папке/db/custom.db
#    (в архиве файл БД с демо-данными уже включён: db/custom.db)

# 4. Если база пустая — создать схему:
bun run db:push      # или: npx prisma db push

# 5. Запуск
bun run dev          # или: npm run dev
```

Откройте **http://localhost:3000** — откроется страница входа.

## 5. Запуск в продуктиве (production)

```bash
bun run build        # сборка (standalone-выход Next.js)
bun run start        # запуск сервера на порту 3000
```

Рекомендации:

1. **Процесс-менеджер.** Держите приложение под pm2 или systemd:
   ```bash
   pm2 start "bun run start" --name mrt-tno-crm
   pm2 save
   ```
2. **HTTPS и домен.** Поставьте обратный прокси (nginx / Caddy / Apache) на порт 3000 и включите HTTPS. Клиенты заходят по доменному имени, прямые порты наружу не открывайте.
3. **Секрет сессий.** В `.env` добавьте собственный `NEXTAUTH_SECRET` (в коде есть только демо-значение для разработки):
   ```bash
   openssl rand -base64 32   # сгенерировать значение
   # .env:  NEXTAUTH_SECRET=<сгенерированное значение>
   ```
4. **Путь к БД.** Убедитесь, что `DATABASE_URL` в `.env` указывает на рабочий файл базы (абсолютный путь).

## 7. База данных и демо-данные

- Вся база — один файл SQLite: **`db/custom.db`**. В поставке он содержит демонстрационные данные (пользователи, города, ЛПУ, номенклатура, статусы, специализации, НВ, заявки, визиты, записи аудита).
- **Начать с чистой базы:** остановите приложение, удалите файл `db/custom.db`, выполните `bun run db:push`, затем создайте пользователей (раздел «Пользователи» или пункт 8).
- **Восстановить демо-данные:** `bun prisma/seed.ts` — пересоздаёт демонстрационный набор (внимание: полностью заменяет данные).

## 8. Пользователи и пароли

- Управление пользователями (создание, редактирование, роли) выполняется в приложении в разделе **«Пользователи»** под учётной записью с ролью МП.
- Пароли хранятся в виде bcrypt-хэшей. Чтобы задать пароль, удобнее всего: войти под `m.ivanova` → «Пользователи» → создать новых пользователей с рабочими паролями → удалить демо-учётные записи (`m.ivanova`, `a.petrov`, `a.sidorova`).
- Альтернативный путь: отредактировать логины/пароли в `prisma/seed.ts` и выполнить `bun prisma/seed.ts` (пересоздаёт все демо-данные).

## 9. Резервное копирование

Резервная копия — это копия файла `db/custom.db`. Выполняйте её регулярно (ежедневно) и храните вне сервера:

```bash
# пример задания cron (в 02:00, хранить 30 копий):
0 2 * * * cp /путь/к/проекту/db/custom.db /путь/к/бэкапам/custom-$(date +\%F).db
```

Восстановление: остановить приложение, заменить файл БД резервной копией, запустить приложение.

## 11. Известные ограничения и примечания

1. **SQLite** рассчитана на работу в рамках одного сервера/файла — для небольших команд этого достаточно. При значительном росте нагрузки возможен переход на PostgreSQL: Prisma-схема переносится без изменений кода интерфейса.
2. Шрифты: основной текст — Montserrat (Google Fonts), акцентный — Arimo. Фирменный шрифт Cygre (коммерческий) **не встроен**; если он установлен локально у пользователя, приложение применит его автоматически.
3. Демо-данные условные и предназначены для проверки функциональности; перед промышленной эксплуатацией их следует удалить (раздел 7).
4. В тестовой среде при автозаполнении форм программными средствами часть полей может не фиксироваться (особенность HTML-инпутов времени); при обычном вводе с клавиатуры/мыши поведение корректное.
5. Экспорт PDF формируется на клиенте и требует интернет-соединения только при первом открытии (шрифты PT Sans лежат локально в `public/fonts/pdf`).
6. Пометка «на удаление» — обратимая операция: физического удаления НВ, ЛПУ, номенклатуры, специализаций и пользователей из интерфейса нет (история заявок и визитов не теряется). Физическая очистка устаревших записей при необходимости выполняется средствами базы данных.
